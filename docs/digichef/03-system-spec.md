# 猛見樂後 DigiChef 系統規格草案

## 系統目標

未來網站與後台不應只是展示餐點，而要真正支援下面四件事：

1. 訂閱制餐盒銷售
2. 門市現場營運追蹤
3. SOP 標準化與版本管理
4. 老闆遠端管理與決策

## 建議的第一版模組

### 產品模組

儲存 A、B、C、D 四種套餐的基本資料：

- 方案代碼
- 名稱
- 主肉種類
- 配方說明
- 營養資料
- 包月價格
- 零售價格
- 標準口感
- 是否上架

### 原料與進貨模組

用來管理原料基準成本與實際進貨：

- 原料名稱
- 單位
- 基準成本
- 供應商
- 進貨日期
- 進貨量
- 進貨單價
- 到貨檢查結果
- 庫存位置
- 附件或照片

### 醃製批次模組

用來追蹤每一批前置作業：

- 批次編號
- 對應方案
- 肉品重量
- 份數
- 配方用量
- 醃製開始時間
- 預計使用日期
- 狀態
- 執行人
- 備註

### 測試與生產模組

用來分開管理 `測試批次` 與 `正式生產批次`：

- 測試編號或生產編號
- 對應方案
- 烤箱模式
- 溫度
- 濕度
- 風速
- 目標芯溫
- 實測芯溫
- 烤前重量
- 烤後重量
- 失重率
- 感官評分
- 照片
- 是否納入 SOP

### SOP 模組

用來保存正式版作業流程與變更紀錄：

- SOP編號
- 流程類別
- 標題
- 版本號
- 生效日
- 步驟內容
- 完成標準
- 必填附件
- 異常處理
- 狀態

### 問題回報模組

用來承接所有異常與待決策事項：

- 問題編號
- 問題分類
- 發生時間
- 描述
- 當下處理
- 是否影響出餐
- 指派給誰
- 狀態
- 回覆紀錄

## 建議權限

### 老闆

- 可看全部資料
- 可修改 SOP
- 可核准正式參數
- 可查看成本與報表

### 員工

- 可新增進貨紀錄
- 可新增醃製批次
- 可新增測試紀錄
- 可上傳照片
- 可提報問題
- 不可刪除正式 SOP

## 自動化需求

第一階段先用手動填表，第二階段建議加上以下自動化：

### 每日提醒

- 上班後提醒員工完成開工盤點
- 下班前提醒員工完成日結

### 異常通知

- 問題回報標記為 `需你回覆` 時，自動通知老闆
- 測試紀錄標記為 `待複測` 時，自動列入隔日待辦

### 成本統計

- 進貨資料自動彙總成本
- 依套餐方案換算單份原料成本與近期波動

### SOP 轉正

- 當某一款方案連續多批測試穩定，可一鍵升級為正式 SOP 版本

## 第一版 UI 建議

若之後要做網站或後台，首頁建議先做三個區塊：

- 今日待辦
- 測試與出餐狀態
- 問題與待決策事項

產品頁不要先做得太花，反而應先把 `產品規格、營養、價格、SOP 狀態` 清楚呈現。你真正的競爭力不是只有菜單，而是 `可遠端管理的標準化營運系統`。

## 第一版開發優先序

1. 後台登入
2. 套餐資料管理
3. 進貨紀錄
4. 醃製批次
5. 測試烤製
6. 照片上傳
7. 問題回報
8. SOP 管理
9. 訂閱制下單
10. 報表與通知
