# 猛見樂後 DigiChef 遠端營運交接手冊

## 目標

這份手冊用來解決一個核心問題：`老闆不在門市，員工仍能依固定流程完成測試、生產、記錄與回報`。

適用起始日是 `2026-04-14`。第一階段不是直接追求大量出餐，而是先把測試流程、紀錄流程與遠端管理節點做穩。

## 角色分工

- 老闆：
  負責定義餐點標準、檢查紀錄、做最後決策、決定是否補貨或複測。
- 門市員工：
  負責現場執行、拍照、填表、回報異常、依核准 SOP 做測試與生產。

## 員工每日必做

1. 上班第一件事先完成開工盤點。
2. 任何進貨都要立刻記錄，不可晚點補寫。
3. 任何醃製都要有批次編號、時間與配方紀錄。
4. 任何測試都要留下溫度、濕度、風速、芯溫、重量、口感評分與照片。
5. 任何異常都要先拍照、再填問題回報。
6. 下班前一定要完成日結。

## 2026-04-14 首日測試任務

首日的重點不是賣，而是確認 A、B、C、D 四款產品的可執行參數。

當天至少要完成：

- A 套餐 1 批測試
- B 套餐 1 批測試
- C 套餐 1 批測試
- D 套餐 1 批測試

每一批都要完成：

- 烤前重量
- 烤後重量
- 實測芯溫
- 外觀評分
- 口感評分
- 多汁度評分
- 出爐照
- 切面照

## 首日執行節奏

### 08:30 - 09:00 開工盤點

- 確認冰箱、冷凍、乾貨、烤箱、器具、工作台與清潔狀況
- 若發現缺料、設備異常、環境未整理完成，先在問題回報表記錄

### 09:00 - 10:00 原料確認與批次建立

- 依照實際原料建立當日進貨與現有庫存紀錄
- 將 A、B、C、D 測試批次編號先建好
- 準備肉品與對應醃料

### 10:00 - 12:00 醃製與測試前準備

- 依配方稱重與加料
- 封袋後立刻貼上批次編號
- 將醃製開始時間寫入線上表單

### 13:00 - 16:00 測試烤製與拍照

- 依每一款方案的標準參數進行第一輪測試
- 每一批出爐後先量芯溫，再秤重，再拍照
- 評估外觀、口感、多汁度與是否要複測

### 16:00 - 17:00 整理紀錄

- 檢查是否所有照片連結都已貼上
- 檢查是否所有重量與評分都已補齊
- 檢查是否每一批都有結論

### 17:00 - 17:30 收班回報

- 回報今天已可採用的參數
- 回報明天要補的原料
- 回報仍不穩定、需要複測的項目
- 回報卡住決策的問題

## 老闆每天遠端要看什麼

1. `每日交接`：員工今天有沒有真的照排程做。
2. `測試烤製`：哪幾批已完成，哪幾批失敗，原因是什麼。
3. `成品照片`：照片是否足夠判斷產品品質。
4. `問題回報`：有沒有需要你即時處理的異常。
5. `進貨紀錄`：是否需要補貨，成本是否開始累積。

## 遇到問題的處理原則

- 若問題會影響出餐或測試結論，先停，不要硬做。
- 若問題是資料沒填完整，先補資料再結案。
- 若問題是照片沒拍，該批不得視為完成。
- 若問題是員工自行改配方或改參數，該批直接標記失效，需重做。

## 成功標準

這一階段只要達成以下四件事，就算交接成功：

- 員工能自己完成開工、測試、拍照、回報
- 老闆不在現場也能看懂當天狀態
- 每一批產品都有可追溯紀錄
- 可以逐步把測試結果沉澱成正式 SOP
